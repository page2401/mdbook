01. 专属标注与元数据（mdBook 0.5 实测）

不同静态网站生成器对“提示框 / 标注（Callouts / Admonitions）”和页面元数据的语法约定存在显著分歧。本文件由原始 GFM 母版派生至 mdBook v0.5.4，直观展示了“必须剥离 YAML Frontmatter”与“0.5 原生直通 GFM Alerts”两大鲜明特征。

1. Frontmatter 元数据机制（实测陷阱：默认不剥离 YAML）

与绝大多数静态站点生成器不同，mdBook v0.5.4 的章节标题与层级完全由全局 book.toml 与 src/SUMMARY.md 索引文件集中声明，内置 pulldown-cmark 默认不会剥离文件顶部的 --- ... --- YAML Frontmatter：

  • 实测现象：若原样保留母版顶部的 ---\ntitle: "..."\ndescription: "..."\n---，mdBook 0.5.4 会把首行 --- 渲染为 <hr> 分割线，并把末尾 --- 当作 Setext 二级标题下划线，将整段 YAML 原文直接印成页面顶部的巨大 <h2> 标题！
  • 派生改造：真实 mdBook 工程（如 The Rust Programming Language）均不在 src/*.md 顶部编写 YAML 元数据；本派生文件按原生惯例移除了顶部 4 行 YAML。

03. 数学公式排版（mdBook 0.5 + KaTeX 0.19）

mdBook 内置的 mathjax-support = true 默认会向页面注入外部 cdnjs.cloudflare.com MathJax 脚本且仅识别 \\(...\\) / \\[...\\]。为实现零外部 CDN 依赖并兼容主流 $...$ / $$...$$ 定界符，本子站在本地打包 katex@0.19.1 + auto-render。注意：由于 pulldown-cmark 先按 CommonMark 规则处理 ASCII 标点反斜杠转义，公式内的换行 \\、间距 \, / \! 以及正文中的字面量 \$ 需双写反斜杠（\\\\、\\,、\\$）。

1. 行内公式与中英文混排基线对齐

考察重点：行内公式在中文字号下的缩放比例、上下标是否撑乱行高，以及分数与根号在行内的紧凑度。

  • 质能方程 $E = mc^2$ 与欧拉恒等式 $e^{i\pi} + 1 = 0$ 嵌入在连续中文段落中的视觉基线表现。
  • 归并排序的平均时间复杂度为 $\mathcal{O}(n \log n)$，而空间复杂度为 $\Theta(n)$；当输入规模满足 $n \ge 2^{16}$ 时，常数因子差异显著。
  • 贝叶斯条件概率公式行内排印：$P(A \mid B) = \frac{P(B \mid A)\,P(A)}{P(B)}$，以及带根号的欧氏距离 $d(\mathbf{x}, \mathbf{y}) = \sqrt{\sum_{i=1}^{n}(x_i - y_i)^2}$。

2. 多行等式对齐推导（aligned 环境）

测试 \begin{aligned} ... \end{aligned} 多行对齐、积分算子与括号自动缩放 \left( ... \right)：

$$ \begin{aligned} I^2 &= \left( \int_{-\infty}^{+\infty} e^{-x^2}\,\mathrm{d}x \right) \left( \int_{-\infty}^{+\infty} e^{-y^2}\,\mathrm{d}y \right) \\ &= \iint_{\mathbb{R}^2} e^{-(x^2 + y^2)}\,\mathrm{d}x\,\mathrm{d}y \\ &= \int_{0}^{2\pi} \int_{0}^{+\infty} e^{-r^2} r\,\mathrm{d}r\,\mathrm{d}\theta \\ &= 2\pi \cdot \left[ -\frac{1}{2} e^{-r^2} \right]_{0}^{+\infty} = \pi \implies I = \sqrt{\pi} \end{aligned} $$

05. 高阶代码块与语法高亮（mdBook 0.5 + hidelines 实测）

1. 代码块文件名标题栏与基础语法高亮（客户端内置 highlight.js）

与其他 Rust/Go 生成器在构建期直出静态 HTML Token 不同，mdBook 内置了一套完全离线的客户端 highlight.js + 一键复制按钮（Copy to clipboard），随页面顶部的 Light / Rust / Coal / Navy / Ayu 五套主题实时切换代码配色。对于文件名标题栏，沿用母版在代码块上方以粗体路径标注：

scripts/resolve-route.ts

export interface RouteContext {
  basePath: string
  slug: string
  cleanUrls: boolean
}

export function formatDocRoute(ctx: RouteContext): string {
  const prefix = ctx.basePath.endsWith('/') ? ctx.basePath : `${ctx.basePath}/`
  const normalized = ctx.slug.replace(/^\/+|\/+$/g, '')
  if (!normalized || normalized === 'index') return prefix
  return ctx.cleanUrls ? `${prefix}${normalized}/` : `${prefix}${normalized}.html`
}

2. 关键行聚焦：mdBook 独门绝技 hidelines（隐藏样板行而非背景高亮）

mdBook 原生不支持 {3,7-9} 或 hl_lines 背景色高亮，但它源自 The Rust Programming Language 官方教程需求，发明了全行业独树一帜的 hidelines（隐藏上下文样板行） 机制：

  1. Rust 代码块默认识别行首 # ：凡是以 # 开头的初始化/断言样板行默认折叠为 <span class="boring">，代码块右上角自动浮现 “👁 Show hidden lines” 切换按钮，既让读者一眼聚焦核心逻辑，又保证整段代码可完整复制编译；
  2. 任意语言自定义前缀 hidelines=...：在非 Rust 代码块（如 json 或 ts）的信息串追加 hidelines=~ ，同样可折叠次要字段，聚焦第 3 行与第 7–9 行关键配置！

use std::path::{Component, Path, PathBuf};

pub fn normalize_rel(raw: &str) -> PathBuf {
    Path::new(raw)
        .components()
        .filter(|c| matches!(c, Component::Normal(_)))
        .collect()
}

pub fn mount_subsite(base_dir: &Path, sub_path: &str) -> Option<PathBuf> {
    let resolved_base = base_dir.canonicalize().ok()?;
    let target = resolved_base.join(normalize_rel(sub_path));
    target.starts_with(&resolved_base).then_some(target)
}

fn main() {
    let out = mount_subsite(Path::new("."), "hugo/05-code-blocks");
    assert!(out.is_none() || out.is_some());
}
